# End-of-session resource reconciliation

This reference adapts the terminal resource audit in [Takazudo/codex-settings cleanup-resources](https://github.com/Takazudo/codex-settings/tree/main/skills/cleanup-resources) to standalone implementation prompts. Read it for **every selected execution environment**. It is especially important for local Grok CLI on Mac/WSL, where the agent has sometimes stopped on a topic branch with unintended working-tree changes. The implementing agent must follow the **inlined procedure below**; do not require it to install or invoke another skill.

## When to run

- Run after the final development/review/verification/integration decision, immediately before the final implementation report. For continuous work, run a scoped reconciliation after each completed wave and a full touched-resource audit at the terminal STOP. Even if a task is blocked, halted, or not merge-authorized, reconcile what is safe and preserve unfinished work; do not defer the audit just because the PR remains open.
- Take a starting snapshot when implementation begins: original branch and commit, `git status --porcelain=v1`, available worktree paths, existing task PRs/branches and known resources. If a snapshot is missing, treat uncertain items as pre-existing, keep them, and report the ambiguity. Avoid repo-wide/org-wide speculative cleanup.
- Apply the same audit principle to Project/cloud managers, CLI parents and delegated workers. A worker audits its own local changes and returns a manifest; **the manager** owns integration and cross-worker reconciliation under the environment policy below. A cloud manager cannot pretend it removed a local worktree on a worker's machine.

## Remote branch policy by execution environment

- **Cloud execution retains remote branches.** For Claude Code Cloud (`-ccc`), Claude Code Cloud Project (`-cccp`), Codex Cloud (`-coc`) and Grok bot cloud (`-grc`), remote-branch deletion is outside terminal cleanup, even after a successful merge. Do not attempt or delegate deletion, call deletion APIs, use `git push --delete` or delete-on-merge options such as `gh pr merge --delete-branch`, queue parent retries, or request deletion permissions. This applies to the manager and all its children, including a **Grok bot cloud manager → Cursor/local worker** arrangement.
- Record surviving remote branches as **kept intentionally**. Their retention is expected completion, not a cleanup failure, warning, blocker or manual cleanup task. Do not probe deletion permissions or invent a denied operation. Read-only remote-state checks, issue/PR reconciliation and safe local checkout/worktree cleanup still apply.
- **Local CLI execution keeps safety-checked remote cleanup.** Apply the local remote-deletion and retry rules below only when a local CLI workflow is selected, not merely because a cloud manager delegates to a local worker. Choose the policy from the selected environment rather than the presence of a cloud flag among allowed candidates. A portable prompt must retain this conditional policy so a later cloud execution never inherits local-only remote-deletion instructions.

## Manifest and audit

List every touched resource with its exact identity, owner/role, status, intended disposition and reason:

- Issues: source, tracker, epic, child, unrelated finding, protected coordination.
- PRs: task/root, child/fix, intentionally held, merged, closed without merge.
- Branches: original/parent, task/topic, integration/base, fix, protected/super-base, foreign.
- Worktrees: exact path, current checkout, workflow-owned temporary, pre-existing/external, stale metadata.
- Working-tree changes: tracked/untracked/ignored generated files; distinguish starting/pre-existing edits, verified intentional deliverables, temporary output and unexplained diffs.

Check live state before acting: `git status --short`, `git diff --stat`, `git diff --cached --stat`, `git branch --show-current`, `git worktree list --porcelain`, relevant issue/PR state, merged commit and remote branch. Check task branch commits are pushed or otherwise durably checkpointed before deleting/checking out. Refresh after any concurrent change. Do not treat an issue or PR as complete solely because code was written or a check passed on another SHA.

## Safe disposition

1. **Protect work.** Never silently discard pre-existing, user-owned, uncommitted, untracked or unexplained changes. Preserve accepted incomplete work on its intended task branch, a commit or explicit checkpoint and identify its location. If a dirty tree prevents checkout/worktree removal, leave it in place and report the exact paths; do not use blanket `git reset --hard`, `git clean -fd`, `git restore .`, `git branch -D`, forced worktree removal, or an automatic stash that hides changes. Remove only individually identified, unequivocally disposable files created by this workflow after confirming they are not deliverables; never infer disposability from an unfamiliar filename. Do not commit generated junk just to obtain a clean status.
2. **Reconcile issues/PRs.** Close only fully accepted and verified integrated delivery issues, children before the parent; preserve unresolved checklist items, coordination, unrelated findings and intentional holds. Leave unmerged PRs and their delivery issues open without merge authority. Do not close intentional open PRs as "cleanup". A merged PR remains as a record; a PR closed without merge is a warning to investigate. Never delete an open super-PR's head/super-base branch, close its super-epic or remove another workflow's resources.
3. **Restore the stable checkout.** When the task work is safely committed/pushed or checkpointed, switch the primary local checkout off the disposable task branch, preferably to the original safe parent branch or the repository default branch. Never switch over dirty/unprotected changes. If an original branch was itself a working branch, preserve it rather than delete it; if a branch is checked out in another worktree, respect Git's refusal. If safe restoration is impossible, report the exact branch/path and blocker, not "clean".
4. **Remove only owned temporary worktrees.** Remove a workflow-created worktree only when its task is safely integrated or explicitly abandoned with no unique work, and the path is neither the active checkout nor dirty; use `git worktree remove <exact-path>`, never `rm -rf` or `--force`. Prune confirmed stale metadata with `git worktree prune`. Keep external/unknown worktrees, unfinished tasks and ambiguous resources.
5. **Delete only dead local branches; apply the remote policy.** Delete workflow-owned local branches only after verifying their work is integrated and no live PR/other work depends on them, using `git branch -d <exact-branch>`; honor refusal. For cloud execution, retain remote branches without attempting deletion. For local CLI execution only, delete a matching remote branch after verifying the PR is merged (or the branch's disposal was separately authorized), its current ref is still the expected one, and no open PR or integration chain needs it. Use authenticated ordinary deletion, never force. With no merge authority or while CI/review blocks integration, **keep the unmerged task branch locally/remotely**, though return the checkout to a safe parent when possible. Never delete default, parent, protected/super-base or other owners' branches.
6. **Verify the end state.** Rerun `git status --short`, `git branch --show-current`, `git worktree list --porcelain` and check relevant remote refs. Aim for a clean stable primary checkout with all intended work available in commits/PRs. If anything remains intentionally dirty or checked out elsewhere, name it explicitly rather than asserting a clean exit.

## Local-only permission denial and parent-manager retry

This remote-deletion retry procedure applies only to a selected local CLI workflow. Cloud managers and their workers do not attempt remote deletion or create a retry queue; intentionally retained remote branches do not make their audit incomplete.

For local CLI delegated work, a child that cannot complete an applicable cleanup action must return the exact repository, branch/ref/path, expected head SHA, associated PR/issue, whether merge is confirmed, attempted action, raw error/permission class and recommended next action. The parent adds eligible local-workflow actions to a cleanup retry queue. Report genuine failures of applicable local checkout/worktree operations in any environment.

The parent independently rechecks live state, ownership, merge/PR dependencies and its own authority. **If allowed**, it retries the denied remote deletion using its authenticated identity; record success or the exact continuing blocker. A child's inability to delete a remote branch is not proof the parent cannot. Equally, manager privileges are not license to bypass branch protection, security boundaries, a hard denial or a user hold. An approval/sandbox escalation is attempted only through supported, authorized facilities; do not loop through the same denied credentials or pretend escalation worked. If the parent also lacks authority, retain the branch and report a human/access action. Local checkout/worktree cleanup remains the responsibility of the worker/host that owns those files, with the parent verifying the returned evidence.

Run the terminal audit **after** child results are integrated and after the final merge/hold outcome; if cleanup is delegated for investigation, the parent performs/authorizes applicable mutations and verifies their results. Report genuine failed or skipped applicable actions. Cloud remote-branch retention is intentional disposition, not a failed or skipped action.

## Final report contract

Finish with a concise `Cleanup audit` section: `Closed issues`, `Removed worktrees`, `Deleted local branches`, `Remote branches`, `Kept intentionally`, `Warnings`, `Ambiguous`, and `Final checkout/status`. Include exact resource identities and reasons; include parent retry results only for applicable local CLI cleanup. For cloud execution, list surviving remote branches under intentional retention without a failure warning or follow-up request. When no changes are needed, still state that the audit ran and report the verified clean checkout or explicit retained state. Do not hide an unfinished PR, retained dirty diff or remote branch.

## Plain-language handoff addition (always inline)

Include this within the **single** standalone execution prompt after the implementation and merge/hold procedure, before its final-report instruction. It applies even when no resources are ultimately created. For a cloud-only prompt, omit the local-only remote-deletion/retry paragraph; for a local-only prompt, omit the cloud paragraph. For a portable or mixed-host prompt, keep both explicitly conditional and apply cloud retention to every worker of a cloud manager. Never substitute a skill name or hyperlink for these instructions.

```text
Before your final report, perform a terminal cleanup audit of the resources this work actually touched. Record the initial checkout/status and pre-existing changes before editing; at the end enumerate associated issues, PRs, local/remote branches, worktrees and tracked/untracked diffs, with their owners and current states. Check live Git and GitHub state before each mutation. Close only fully verified, integrated issues (children before parents); preserve incomplete issues, protected coordination and intentional open PRs. Do not delete the branches of unmerged/held PRs, an open integration/super-PR or another owner's work.

Protect all pre-existing, unexplained and uncommitted work. Finish or checkpoint intended edits on the task branch; remove only individually identified disposable output you created, never blindly discard unknown diffs. Do not use git reset --hard, git clean -fd, git restore ., git branch -D, forced worktree removal or a blind automatic stash. After safely recording task work, return the primary local checkout from the task branch to its safe original parent/default branch when possible, without overwriting dirty work. Remove only clean, workflow-owned temporary worktrees via git worktree remove; prune confirmed stale metadata. Delete only confirmed merged, unused workflow-owned local branches with git branch -d, honoring refusal. If a task PR is still open, retain its branch even if you can switch the primary checkout away from it.

For cloud execution, retain remote branches intentionally. Do not attempt, delegate or retry remote branch deletion, request deletion permissions, or use delete-on-merge options. This applies to Claude Code Cloud with or without Project, Codex Cloud and Grok bot cloud, including every child or external/local worker managed by a cloud session. Retaining remote branches is expected completion, not a warning, blocker or manual cleanup task.

For local CLI execution only, delete a remote task branch only after verifying ownership, its expected current ref, confirmed integration and absence of live PR dependencies. If a delegated worker lacks permission, report its exact repository, ref and expected SHA, related PR and merge state, attempted operation and raw error to the parent manager. The parent must independently recheck safety and, only when its own permissions and repository policy authorize it, retry the deletion using its own credentials; otherwise retain the branch and document the blocker. Do not apply this procedure to workers managed by a cloud session or bypass explicit denials or branch protections.

The parent owns the cross-worker cleanup ledger, while each local worker owns its machine's worktrees and checkout. Finally rerun git status --short, git branch --show-current and git worktree list --porcelain (where a local checkout exists), and verify relevant remote refs read-only. Report a Cleanup audit with closed/kept issues, removed/kept worktrees, deleted/retained local branches, remote branch disposition, genuine warnings, ambiguous items and the exact final checkout/diff status. Include remote deletion/retry results only for an applicable local CLI workflow. Never claim clean completion if unintended changes, an unreturned task checkout or an applicable failed cleanup remain; intentionally retained cloud remote branches do not prevent completion.
```
