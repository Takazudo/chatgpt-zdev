# Session artifact storage

For every zdev session, save user-facing files created during planning or prototyping to the connected Dropbox under `/codex-artifacts/<session-folder>/`, including intermediate prototype rounds, accepted source, assets, screenshots and the final artifact ZIP when produced. Do this as files are produced, not only at the final handoff. Preserve useful relative paths and round names. Do not upload transient scratch files, secrets, or unrelated user files. Respect any more specific user instruction.

Use the Dropbox connector and its applicable upload workflow; follow its confirmation, permission, file-type, conflict and size requirements. The user’s instruction to use this destination does not override a connector’s required confirmation. Create missing parent folders in order when authorized. Pick one descriptive, filesystem-safe session folder name with a date and unique suffix, check for collisions, and reuse it throughout this session; never overwrite another session or an existing file. When a file changes, use a distinct versioned name unless the available connector and user authorization explicitly permit replacement.

Upload the actual generated files, retaining their extensions and bytes where supported. Create and validate the implementer ZIP when required by the handoff and upload it too; Dropbox storage supplements the readable brief. Report the exact Dropbox folder and saved paths, and distinguish successful uploads from pending or failed ones. Do not claim success without a successful connector response. Do not create public or shared links unless requested.

If Dropbox is unavailable, permission or confirmation is pending, or a file cannot be uploaded, explain the specific blocker and provide the available Chat attachment/download as a fallback. Continue independent planning. Do not imply a Dropbox path is automatically accessible to a separate local or cloud implementation session: verify destination access, or identify the exact files and request transfer when indispensable. If no deliverable files exist, create no empty session folder and state `Artifacts: none required`.
